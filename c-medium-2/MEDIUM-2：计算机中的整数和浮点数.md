3.为什么底层用**补码**？

**原码**：最高位当符号位，其余为绝对值。**反码**：负数按位取反。**补码**：负数按位取反加一

补码的核心好处我认为有三个：补码的零是唯一的，补码的**加减法统一**（根据模2^n同余的数学性质推导），8，16，32字节符号扩展时不出错。

解释：当两个不同类型的数进行运算时，会自动向范围更大的转换（**隐式类型转换**）。原理：1.整数提升，2.有符号的值不能完全表示无符号的值，有符号转无符号。反之则无符号转有符号。

## Step3：丝滑配比阀 —— 认识IEEE 754标准下的浮点数

**【任务 3.1：对学长提示的深入理解】**

1.float：符号位（sign）1位，阶码（exponent）：8位，尾数（fraction）：23位。

   double：（sign）1位，（exponent）：11位，（fraction）：52位。

2.偏置值=$(2^{k-1}-1)$，其中k等于指数域位数（8or11）。意义：**方便比较大小，保留特殊编码**

**解释**：**比较大小**：当需要比较阶码时，直接按位比较（无进位链，符号判断等，速度快），不需要加减，也就没有任何溢出的风险，并且逻辑更直观。**特殊值编码**：全零（转化为非规格数或零的标志），全一刚好落在两端，其中，全一留出来表示NaN（阶码全一，尾数非零）和无穷（阶码全一，尾数为零）。

3.非规格化数的特点：这个设计很巧妙，加上偏置后，阶码（exponent）全零时，已经是一个非常小的数（float：约`2^-126`）此时为了表示更小的数（设计上是**向零平稳过渡**）就默认最前面的**“整数”由一变为零**，然后实际上真正的有效数字从**尾数（fraction）**中开始，所以非规格数牺牲了一定的有效精度，为了表示出更小的数。**示意图如下**

## Step4：消失的营业额 —— 浮点加法、舍入与结合律

**【任务 4.1：设计加法程序】**

1.为什么**小阶向大阶看齐**？小阶向大阶看齐要右移（**为扩大阶码准备**），反之左移。右移通常损失的是尾数末端的低位信息。左移如果超出尾数可用的位数，则可能破坏高位的有效信息。后者通常更加不利。并且右移造成的精度损失，则可以通过保护位、舍入等机制尽可能减小。（左移不知道有没有这种机制）

2.**四种**可选的舍入处理方法：

| 舍入方式                 | 核心规则                                                     |
| ------------------------ | ------------------------------------------------------------ |
| 舍入到最近值，平局取偶数 | 选择距离精确结果最近的可表示值；恰好等距时，选择末位为偶数的那个 |
| 向零舍入                 | 丢弃超出精度的部分，不向远离零的方向进位                     |
| 向正无穷舍入             | 选择不小于精确结果的最小可表示值                             |
| 向负无穷舍入             | 选择不大于精确结果的最大可表示值                             |

3.八位迷你浮点系统：

```c
#include <stdio.h>
int main(){
    char count1[9];
    char count2[9];
    scanf("%8s %8s",count1,count2);

    unsigned char a=0,b=0;
    for(int i=0;i<7;i++){
        a|=count1[i]-'0';
        a<<=1;
        b|=count2[i]-'0';
        b<<=1;
    }
    unsigned char exponentA=a>>3;
    unsigned char exponentB=b>>3;
    unsigned char significandA=8|(a&7);
    unsigned char significandB=8|(b&7);
    unsigned char exponent=0; 
    int r;
if (exponentA >= exponentB) {
    r = exponentA - exponentB;
    significandB >>= r;
    exponent = exponentA;
} else {
    r = exponentB - exponentA;
    significandA >>= r;
    exponent = exponentB;
}
    unsigned int t=significandA+significandB;
    if(t>=16){
        t>>=1;
        exponent+=1;
    }
    unsigned char fraction=t&7;
    unsigned char result=0;
    result|=(exponent<<3)|fraction;
for (int i = 7; i >= 0; i--) {
    printf("%u", (result >> i) & 1u);
}
printf("\n");
    return 0;
}
```

**【任务 4.2：老板为什么每天都在亏钱？】**

核心原因：浮点数的精度有限制！下面以float类型举例。float中的fraction为23位，将二进制能表示的所有值对应到十进制：
$$
2^x = 10^y，
2^{24} = 16777216 = 1.6777216 \times 10^7
$$
说明float型数的有效精度为七位有效数字，而老板的money居然有10^20^

因此，老板的21位数字，float所能记住的大概只有7位，后面的位只能舍入。因此被改造成
$$
1e20f≈1.0000000200408773×10^{20}
$$
这就是所谓的**精度丢失**。

**数学原理如下：**
$$
10^{20}≈1.3552527156068805 \times 2^{66}
$$

float 尾数只能保留 23 位：
$$
0.3552527156068805 \times 2^{23} \approx 2980075.77
$$

四舍五入：
$$
2980075.77 \rightarrow 2980076
$$

实际尾数：
$$
1 + \frac{2980076}{2^{23}} = 1.355252742767334
$$

实际值：
$$
1.355252742767334 \times 2^{66}
= 100000002004087734272
\approx 1.0000000200408773 \times 10^{20}
$$
所以可以解释15块钱凭空消失的原因（**大数吸收**）：15元太少了，在**对阶**的过程中15（1.875*2^3^）要右移63位才能与-1e20f的**指数对齐**，直接变成0了。daily_expense加上15后根本不会影响结果。而初始资产与支出的净值是相反数，相加后直接变为0，0与15.0进行运算则正常进行。

所以，老板，这15 块不是丢了，是被浮点数的精度限制吞掉了。
